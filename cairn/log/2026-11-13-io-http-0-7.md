# Move to io-http 0.7

The io-http requirement went from 0.6 to 0.7 (Cargo.toml and Cargo.lock, one io-http in the graph). No source line had to change: the coroutines only use `HttpRequest`, `Http11Send`, `Http11SendError`, `HttpSendOutput`, `HttpSendYield` and `HttpAuthBasic`, none of which changed shape for a caller that never serialises a request itself. The bump is breaking all the same, because `HttpRequest` and `Http11SendError` are part of the public API (every coroutine takes the first and wraps the second in its send error variant).

What moves with it is behaviour. io-http 0.7 validates the request head, so a request whose method or header name is not a token, whose header value holds a CR, a LF or a NUL, or which sets `Transfer-Encoding`, no longer reaches the wire: `Http11Send::new` stays infallible and the first `resume` ends with `Http11SendError::InvalidRequest`. Each coroutine already converts `Http11SendError` into its own error enum through `#[from]` (`SendHttpRequest`, `SendHttpRefresh`, `SendHttpRevoke`, `SendHttpRegister`), so the failure is typed without a new variant. The std client builds its own head from the endpoint URL and a base64 Basic credential, neither of which can hold a line break, so only a caller-built `HttpRequest` can trip it. The other 0.7 changes reach the coroutines unseen: interim 1xx responses are skipped, a chunked body is checked for its CRLF and its trailers are read, and the new `Http11SendError` variants flow through the same `#[from]`.

No change folder: nothing was designed here, the crate takes what the dependency now does.

Capabilities moved: `coroutines` (Invalid request head added).

Verified: the new `a_header_value_holding_a_line_break_fails_before_any_write` in src/rfc6749/access_token_request.rs resumes an authorization code exchange whose request carries a header value with a CRLF and gets `SendHttpRequest(InvalidRequest(InvalidHeaderValue("X-Tenant")))` at the first step. It cannot be run against io-http 0.6, where the variant does not exist. `cargo fmt`, `cargo clippy --all-features --all-targets -- -D warnings` clean, `cargo build --no-default-features` clean, `cargo test --all-features` passed (73 unit, 10 doc), `cargo publish --dry-run --allow-dirty` packaged and verified against the registry.
